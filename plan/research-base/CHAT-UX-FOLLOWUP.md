# Postudio 채팅 UX 후속 구현

## 구현 순서

1. 메시지 시각과 스크롤 복원: 기존 TXT/MD 및 채팅 완료 경로에 영향 없는 변경부터.
2. 메시지 저장 멱등성과 전송 대기열: 통신 단절에도 중복 저장·생성하지 않는 계약부터 만든다.
3. PDF와 이미지: 업로드·처리·삭제 공통 기반 이후 PDF, 이미지 순으로 출시한다. 태스크 간 공유 파일(`chat_store`, 일반 채팅 라우트)은 순차 통합한다.

## 1. 날짜 구분선과 스크롤

- 신규 서명된 `ChatEvent::Message`에 서버 UTC 시각 `createdAtUnixMs`를 추가하고, 조회 API에도 노출한다. 기존 이벤트는 필드가 없으면 직렬화에서 생략한다. 기존 바이트·서명·해시 체인이 그대로 검증되는 혼합 버전 fixture를 추가한다. 시각은 표시용이며 기존 인과 순서, 분기 구성, 페이지 커서를 바꾸지 않는다. 오래된 기록에는 날짜를 추정해 넣지 않는다.
- 선택된 분기의 메시지를 브라우저 시간대 날짜로 묶어 날짜가 바뀌는 곳에 한 번만 구분선을 표시한다. 이전 페이지를 붙였을 때 경계에 같은 날짜가 두 번 생기지 않는다. 시각 누락 메시지 때문에 동일 날짜를 쪼개지 않는다.
- 탭 세션에 `호스트 origin + chatId + 분기`별로 보이는 첫 메시지 ID와 그 요소의 뷰포트 상대 Y 오프셋, 바닥 고정 여부만 저장한다. 텍스트와 초안은 추가로 저장하지 않는다. 이전 페이지 prepend 및 복원은 `scrollHeight`가 아니라 메시지 앵커 기준으로 보정한다.
- 앵커가 첫 페이지에 없으면 기존 커서 API로 최대 3페이지를 찾아본다. 없으면 선택된 분기의 최신 구간으로 내려가고, 재조회 루프는 돌지 않는다. 사용자가 아래쪽에 있을 때만 새 답변을 따라간다. 위로 올렸다면 새 답변 도착은 아래로 이동 버튼으로 안내한다.
- 합격: 자정·시간대, 이전 기록 혼재, 페이지 경계, 분기 전환, 390px에서 뒤로 가기·새로고침 후 앵커 유지와 중간 기록 읽는 중 자동 스크롤 방지.

## 2. 전송 대기열

- 브라우저의 origin별 IndexedDB에 명시적으로 보낸 사용자 메시지만 넣는다. 작업 키는 무작위 `clientMessageId`, 내용은 채팅/부모/텍스트/선택 모델·계정·호스트/준비된 첨부 ID다. 자동으로 다른 부모·계정·호스트를 선택하지 않는다. 초안 편집과 대기는 별개로 유지한다. 첫 버전은 선행 작업이 확정되지 않은 메시지의 연쇄 큐잉을 허용하지 않는다.
- 서버는 `(chatId, clientMessageId)`와 정규화한 요청 내용의 해시를 **메시지 저장과 원자적으로** 기록한다. 같은 키·내용에는 이미 저장한 메시지를 돌려주고, 내용이 다르면 409로 거부한다. 키 조회 API는 소유자 인증 아래 둔다. 서버 재시작 뒤에도 같은 결과여야 한다. 진행 중 모델 생성은 기존 완료 claim으로 조회하며 메시지 저장과 생성 상태를 혼동하지 않는다.
- 상태: `전송 대기 → 전송 중 → 저장 확인 → 응답 생성/완료`, 통신이 끊겼으면 `저장 여부 확인 중`, 입력 또는 권한 오류는 `조치 필요`. 연결 회복 시 **요청을 보내지 않았음이 확실한 작업만** 자동 제출한다. 전송이 시작된 상태는 먼저 키를 읽어 확인하고, 미확정이면 자동으로 생성하지 않는다. 멱등성이 보장되지 않는 구버전 호스트는 자동 전송하지 않는다. 모델 응답의 결과가 불명확할 때는 새 키를 만들거나 중복 추론하지 않는다.
- 채팅별 동시 전송 1개. 여러 탭이 동시에 drain해도 서버 키로 중복 저장을 막는다. 전송 전 항목은 취소 가능, 전송 이후는 기록 확인으로 전환한다. 연결 시도는 제한된 백오프(최대 5회)와 수동 재시도 버튼. 로그아웃 시 로컬 대기 데이터 삭제 경로를 제공한다.
- 합격: 보내기 직전/저장 직후 응답 유실/모델 호출 중/브라우저 새로고침/노드 재시작/두 탭 경쟁 각각에서 메시지 중복 저장·모델 자동 재호출이 없고, 계정·호스트·분기 선택이 보존된다.

## 3. PDF와 이미지

- 기존 TXT/MD의 인라인 `textFiles`는 유지한다. 신규 형식은 신뢰 리스너의 소유자 인증 아래 별도 업로드 API로 받으며, 메시지에는 불변 첨부 ID와 형식·크기·처리 상태만 연결한다. 원본 바이트는 `state-dir`의 전용 저장소에 두고, 현재 전체 스냅샷 동기화에 넣지 않는다. 업로드 완료 전 삭제 가능, 실패 사유 표시, 임시 파일 TTL, 보관 한도와 고아 파일 정리를 둔다. 파일명과 클라이언트 MIME을 신뢰하지 않는다.
- PDF: 원본 최대 50 MiB, 200쪽을 1차 상한으로 둔다. 분리된 제한 프로세스에서 텍스트와 쪽 번호만 추출한다. 네트워크 없이 실행하고 실행 시간·메모리·출력 길이를 제한한다. 화면에 `업로드 중 → 읽는 중 → 준비됨/실패` 표시. 암호 PDF·손상·텍스트 없는 스캔은 구분하며 OCR은 별도. 모델에 실제 전달되는 분량과 쪽 범위를 알리고, 모델이 본문 전체를 읽었다고 표시하지 않는다.
- 이미지: PNG/JPEG/WebP부터. 최대 10 MiB 및 디코딩 픽셀 수 제한, 재인코딩으로 메타데이터 제거·썸네일 생성. 입력 붙여넣기와 드롭은 같은 검증 파이프라인을 사용한다. SVG·HTML 및 애니메이션은 첫 버전에서 거부한다. 이미지 지원이 확인된 모델만 원본 대신 처리된 이미지를 전달한다. 미지원 모델에서 파일을 텍스트로 대충 바꾸거나 조용히 누락하지 않는다.
- 피어: 기본은 첨부 저장 호스트 실행. 원격 계정 선택 시, 인증된 피어 채널로 해당 요청에 필요한 제한된 추출 텍스트/처리 이미지 전달 계약을 추가하기 전에는 전송을 막고 이유를 안내한다. 다른 호스트의 기록에는 첨부 메타데이터와 원본 호스트를 표시하되, 파일이 없으면 다운로드 버튼을 만들지 않는다. 원본 전체 복제는 별도 설계다.
- 합격: 용량 초과, 확장자 위장, 암호 PDF, 이미지 픽셀 한도, 업로드 중 탭 종료, 파일 권한, 미지원 모델, 피어 오프라인에서 명확히 실패. 데스크톱 1440px·모바일 390px에서 성공/실패/복구 상태 확인.
