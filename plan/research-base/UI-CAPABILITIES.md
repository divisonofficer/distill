# Studio: CLI 기능 매핑과 대화 유형 분리

## 결정과 구현 경계

Studio는 별도 모델 실행기를 만들지 않고 Distill의 기존 실행·모델·계정 기능을 웹에 노출한다. 기능 이름만 같은 가짜 UI를 만들지 않는다. 일반 대화를 코딩 세션의 이름만 바꿔 제공하지 않는다.

| CLI 기능 | Studio 표면 | 백엔드 | 현재 범위 |
|---|---|---|---|
| 모델 목록·변경 | 새 대화/세션의 모델 선택 | `x.ai/models/list`, `session/set_model`, 생성 `_meta.modelId` | 구현됨. 로컬 검사 및 Orca 확인 |
| 계정 목록·추가·이름 변경·로그아웃·삭제·사용량 | 설정의 호스트별 계정 관리 | 고정 인자의 `distill accounts` 명령 | 구현됨. 로컬 검사 및 Orca 확인 |
| 계정 로그인 | 호스트 계정 연결 | 제공자 OAuth/device-code | 웹 로그인 중계 미구현. 해당 호스트 CLI 안내만 제공 |
| 모델별 계정 라우팅 | 계정/모델 연결 설정 | `accounts routing get/set` | 후속 작업. 모델 선택과 계정 선택을 혼동하지 않음 |
| 세션 조회·재생·승인·질문·계획 검토 | 코딩 대화 | 기존 leader/ACP | 구현됨 |
| MCP·플러그인·메모리·워크플로 | 설정/세션 작업 메뉴 | 기존 CLI/확장 API별 매핑 | 별도 검증 후 노출 |

계정 API는 소유자/Origin 검사를 거친다. 명령 문자열을 셸에 전달하지 않고 고정 argv만 실행한다. 토큰·키·인증 파일 내용과 오류 로그 원문을 브라우저에 반환하지 않는다. 계정 변경은 호스트 범위이며 로그아웃/삭제는 명시적인 사용자 확인을 받는다.

## 일반 대화와 코딩 대화

### 일반 대화

- 사용자 관점에서는 실행 호스트·프로젝트 경로를 선택하지 않는다. 대화 ID가 기기에 종속되지 않는다.
- 로그인한 여러 기기는 동일한 서버 측 메시지 기록·첨부·모델 설정을 읽는다. 브라우저 localStorage를 대화 원본으로 사용하지 않는다.
- 초기 구현은 상주 서버 한 곳이 원본을 보관하고 여러 기기가 접속하는 구조로 시작할 수 있다. 이것은 다중 호스트 복제/장애 전환과 별개다. 기존 P3의 원장 복제 설계를 구현한 것으로 간주하지 않는다.
- 모델 요청에 포함할 컨텍스트는 서버의 확정된 대화 기록에서 구성한다. 턴 순서·중복 전송·동시 기기 입력을 서버에서 직렬화하고, 재접속으로 프롬프트를 다시 실행하지 않는다.
- 기본적으로 터미널·파일 수정·임의 호스트 명령 실행 권한을 주지 않는다. 일반 대화에 도구를 추가할 때는 별도 명시적 권한을 정의한다.

### 코딩 대화

- 대화는 실행 호스트와 프로젝트/worktree를 소유 정보로 가진다. 브라우저는 어느 기기에서든 접속할 수 있지만 실행 위치를 자동으로 바꾸지 않는다.
- UI는 대화 제목과 별도로 실행 호스트, 프로젝트 경로, 연결 상태를 표시한다. 접속 중인 웹 서버와 실제 실행 호스트를 구분한다.
- 호스트가 오프라인이면 읽기 가능한 기록과 실행 불가 상태를 구분한다. 다른 호스트로 재연결하는 것만으로 실행 세션이 이동했다고 표시하지 않는다.
- 모델·계정은 실행 호스트에서 사용 가능한 항목을 선택한다. 일반 대화의 기본 계정과 코딩 호스트의 계정을 혼동하지 않는다.

## 일반 대화 구현의 선행 조건

현재 빌드는 `process_chat_mode_enabled()`가 false이며 chat-kind 세션을 거부한다. `_meta["x.ai/session"].kind="chat"` 경로가 남아 있어도 활성 런타임이 아니다. 또한 해당 chat 경로는 no-op persistence를 사용하므로 단순히 플래그를 켜는 것으로 다중 기기 컨텍스트 공유가 완성되지 않는다.

구현 전 아래 조건을 충족해야 한다.

1. 일반 대화용 실행 프로필과 도구 제한을 정의하고 실제 코드 경로로 검증한다.
2. 사용자별 영속 대화/첨부 저장소와 새 대화·목록·로드·전송 API를 구현한다.
3. 두 브라우저에서 동일 대화 재개, 동시 입력 순서, 중복 요청 방지, 서버 재시작 후 기록 복구를 테스트한다.
4. 이후 일반/코딩 내비게이션을 분리한다. 일반 대화가 준비되기 전 작동하지 않는 전환 탭을 완료 기능처럼 노출하지 않는다.
5. 여러 호스트 복제·오프라인 쓰기·충돌 수렴은 기존 P3의 별도 승인/검증 범위로 남긴다.

CLI 일반 대화가 이미 작동한다는 가정은 소스 조사로 부정되었다. 따라서 이번 CLI 매핑 작업과 일반 대화 백엔드는 별도 구현 단계로 관리한다.

## 검증 기록

모델/계정 worker 결과를 통합하고 독립 리뷰를 수행했다. node 테스트 65개, 웹 check/build가 통과했다. Orca에서 새 세션 모델 선택·로드 후 유지, 활성 세션 선택 요청, 호스트 계정 목록·추가·이름 변경·사용량·삭제 취소·로그아웃·삭제를 확인했다. 모든 계정 조작은 임시 샌드박스에서만 수행했다. 390px iframe에서 계정 화면의 가로 넘침이 없었다.

모델 서버는 `test-model` 하나만 제공하므로 다른 실서비스 모델 간 전환은 브라우저에서 검증하지 않았다. 성공·실패 모델 전환은 가짜 ACP 서버 테스트로 확인했다. OAuth 웹 로그인, 계정 라우팅 편집, 일반 대화 런타임·다중 기기 영속 컨텍스트는 아직 구현하지 않았다.
