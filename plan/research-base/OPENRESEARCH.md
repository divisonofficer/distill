# OpenResearch 연구 작업공간

## 구현 범위

연구 작업공간은 연결 상태, 프로젝트 등록, 기준 실험과 자식 실험 생성, 로컬 실행 제출·취소, 로그 조회, 논문 검색, 프로젝트 파일 메타데이터를 제공한다. 실행과 취소는 명시적 승인 뒤 수행한다. 프로젝트는 기존 Git 저장소만 등록하며 GitHub 동기화는 비활성화한다. 로그는 최대 64 KiB 단위로 읽고 페이지 식별자를 유지한다. 논문 검색은 AlphaXiv 링크를 제공한다. 파일 탐색은 이름·경로·크기·종류 메타데이터만 반환하며 파일 다운로드는 제공하지 않는다.

승인 화면은 호스트·명령·브랜치를 확인한다. 실제 커밋은 요청 시점에 엔진이 선택하고 실행 기록에 저장한다. 승인 전에 특정 커밋을 고정하는 기능은 이번 구현에 없다.

전체 OpenResearch 기능은 구현된 것이 아니다. 캘린더, PPT, Potero 서지관리, LaTeX 작성, Overleaf, SSH 실행, 지표 비교 차트는 이번 구현 범위 밖이다.

## 빌드와 배포

저장소는 Distill 저장소의 형제 경로 `../OpenResearch`에 둔다. 아래 명령으로 실제 사용한 upstream 커밋을 받는다.

```sh
git clone https://github.com/alphaXiv/OpenResearch.git ../OpenResearch
git -C ../OpenResearch checkout cb75d884e76f06ff69cb6a29b9dae44f5f03b4a6
```

`scripts/setup-openresearch.sh`는 해당 checkout과 Rust 1.100.0을 확인하고, Node.js 22 이상과 pnpm 12.16.1로 UI를 빌드한 뒤 macOS ARM64·x86_64 호스트 바이너리를 포함해 release CLI를 빌드한다. 사전 설치할 pnpm 전역 패키지는 필요 없다. 실행 파일은 형제 저장소의 `target/release/orx`에 생긴다. UI와 호스트 번들은 설치 스크립트가 함께 빌드한다.

배포 바이너리는 OpenResearch 0.2.27, SHA-256 `ac71ecf7cbd26a58e991a3cae74409b8c0e9b04b8b865dac2119e15a530663c2`이며, 원본 checkout은 위 커밋이다. 공식 v0.2.27 태그는 다른 커밋이므로 이를 대신 사용하지 않는다. 현재 Distill 메인 노드는 `5174` 웹 UI에서 `7410` 포트로 실행 중이며, `--openresearch-bin`에는 위 형제 경로의 실행 파일 절대 경로를 지정했다. 노드는 `--owner me@example.com`, `--listen tcp:127.0.0.1:7410 --untrusted-listen tcp:127.0.0.1:7411`, 기존 리더 소켓 `$HOME/.distill/postudio/leader-execution-v5.sock`를 사용한다. Vite `5174`는 재시작하지 않았다. 노드의 일반 상태는 기존 `~/.distill/postudio`를 유지하고 연구 런타임은 `state/research/openresearch`에 격리한다.

서비스나 개발 서버를 다음에 시작할 때도 `--openresearch-bin` 또는 `POSTUDIO_OPENRESEARCH_BIN` 설정을 유지해야 한다. 실행 중인 프로세스의 플래그를 OS 서비스 설정으로 자동 저장하지는 않는다.

연결은 사용자가 명시적으로 선택할 때만 시작된다. 노드는 환경을 초기화한 자식 프로세스에 `PATH`와 `TMPDIR`만 보존하고 격리된 `HOME`, `ORX_DATA_DIR`, `ORX_CACHE_DIR`, `XDG_CONFIG_HOME` 및 업데이트 검사 비활성화를 설정한다. 실행은 `--no-telemetry up --host 127.0.0.1 --port <노드가 예약한 포트> --no-browser --no-agent`를 사용한다. Upstream `up.rs`의 설명상 `--no-agent`는 시작 시 하네스 검사를 막지 않는 시험 옵션이며 실제 모델 호출 방지책이 아니다. 프로젝트 생성 시 명시적으로 빈 `starterAgent`를 보내 자동 에이전트 선택 fallback을 막는다. API 경로와 실행은 격리된 HOME·환경에서 수행한다. 사용자 자격 증명이나 descriptor 토큰은 출력하거나 기록하지 않는다.

OpenResearch는 브라우저에서 직접 접근하는 별도 서비스가 아니다. 노드는 연구 포트를 예약한 뒤 공유 차단 목록에 먼저 등록하고 런타임을 시작한다. `/api/ports`는 이 포트를 숨기고 비신뢰 `/p/<port>` 프록시는 HTTP와 WebSocket 모두 거부한다. 노드 재시작 시에도 기존 런타임 descriptor의 포트를 리스너 시작 전에 차단한다. 연구용 HTTP 클라이언트는 환경 프록시와 리다이렉트를 사용하지 않는다. 같은 호스트에서 별도로 실행하는 구버전 노드나 다른 임의 포트 프록시는 이 노드의 차단 정책을 공유하지 않으므로 별도로 업데이트하거나 종료해야 한다.

## 검증 및 한계

실제 브라우저에서 API 가로채기 없이 프로젝트 등록, 기준·자식 실험 생성, 성공 종료 코드 0, 실패 종료 코드 7, 취소, 로그 표시, 새로고침 후 세 실행 복원, 런타임 정지 후 연결 끊김·실행 비활성화·재연결 및 동일 프로젝트·로그 복원을 확인했다. AlphaXiv 검색은 결과 8건과 논문 팝업을 확인했다. 파일 화면은 실제 `reports/verification.txt` fixture의 메타데이터를 확인했다. 이 fixture는 임시 검증 데이터이며 운영 프로젝트로 간주하지 않는다.

노드 전체 테스트 176건과 빌드는 통과했다. 프런트엔드 집중 테스트 29건, 타입 검사(오류·경고 0건), 빌드는 통과했으나 전체 프런트엔드 테스트는 194건 중 191건 통과, composer/speech 기존 테스트 3건 실패했다. 해당 테스트 대상은 연구 변경에서 수정되지 않았다. 이전 upstream 스모크 실행은 HOME을 격리하지 않아 프로젝트 생성 시 일회성 에이전트 호출 가능성을 배제하지 못했다. 실제 모델 호출 여부는 확인되지 않았다. 이를 모델 실행이 없었다는 증거로 해석하지 않는다.

보안 수정 뒤 실서버에서 연구 포트의 HTTP·WebSocket 프록시가 모두 403이고, `/api/ports`에서 해당 포트가 제외되며, 일반 웹 앱 포트 프록시는 200인 것을 확인했다. 연구 서버가 이미 살아 있는 상태로 별도 검증 노드를 시작해 연구 API 호출 전부터 포트가 차단되는 것도 확인했다. 수정 후 실제 로컬 실행과 70 KB 로그의 64 KiB 다음 페이지 접근을 다시 검증했다. 공유 화면 9개를 두 화면 크기에서 방문한 18개 조합에서 가로 넘침과 JavaScript 예외가 없었고 모바일 연구 메뉴의 Escape 초점 복귀를 확인했다.

## 롤백

연구 기능을 되돌리기 전 실행 중인 연구 작업과 승인 대기 세션을 확인한다. 실행 중인 연구 작업이 있으면 연결을 유지하고 기능 비활성화를 보류한다. 안전한 시점에 메인 노드를 종료하고 `--openresearch-bin` 플래그를 제거한 빌드로 재시작한다. 포트 차단 보안 수정은 기능 비활성화 때도 유지한다. 차단 기능이 없는 구버전 노드로 되돌릴 때는 종료된 연구 작업을 확인하고 전용 `orx`를 먼저 중지해야 한다. 연구 데이터는 프로젝트와 실행 기록을 보존하려면 삭제하지 않는다. 필요할 때만, 연구 실행이 남아 있지 않은 것을 확인한 뒤 전용 `state/research/openresearch`를 별도로 삭제한다. 다른 Distill 상태나 OpenResearch 사용자 파일은 건드리지 않는다.

노드 재시작 뒤에도 `orx` 프로세스가 살아남을 수 있다. 프로세스 그룹 전체를 종료하지 않는다. 정리해야 한다면 실행 PID만 확인해 해당 `orx` 프로세스만 중지한다. 검증 중 이전 노드는 모든 세션이 유휴 상태이고 previewkeeper가 유지된 뒤 중지했으며 200개 세션 ID를 보존했다. 임시 7430 서버는 PID만 지정해 중지했고 `orx`는 종료하지 않았다.
